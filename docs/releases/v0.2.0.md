# Cross-Agent Handoff v0.2.0

Rotate between Claude Code, Codex, Antigravity and other agents, or between accounts of one
agent, on the same project folder, including game, video and motion-graphics work. The
project files remain the source of truth; everything new is opt-in.

## What's new

- **Detect an abrupt stop.** `scripts/inject.py` prints resume context and warns when files or
  commits are newer than the checkpoint, which is what a usage limit leaves behind. It works
  on every host, with or without hooks.
- **Mechanical snapshots.** `scripts/snapshot.py` records Git state, recently changed files and
  media size/time in a self-ignored `.handoff/auto/` folder. It needs no model.
- **Opt-in hooks.** `scripts/hooks.py` installs them only on request. Claude Code: session
  start, Stop, StopFailure (including rate limits) and PreCompact. Codex: session start, Stop
  and PreCompact, after trust in `/hooks`. Antigravity: session start and Stop. An optional
  guard asks once to refresh a stale checkpoint. The Claude plugin itself ships no hooks.
- **One-command install and doctor.** `scripts/install.py --hosts claude,codex,antigravity`
  writes the two folders that reach all eight documented hosts. `--doctor` reports edited,
  drifted or missing copies; `--update` and `--uninstall` keep project records.
- **Advisory lock and switch log.** `scripts/lock.py` makes a second writer visible and logs
  each switch. A held lock is taken over only after you confirm the other session stopped.
- **Profiles.** `Profile: game`, `video` or `motion` adds a compact checkpoint section. The
  video and motion sections record running renders, so the next agent checks output instead of
  re-rendering.
- **Optional metadata.** `updated_at`, `language` (checkpoint prose in your language) and `profile`.

## Upgrading from v0.1.1

- No migration is required. The format stays `cross-agent-handoff/1`, existing checkpoints
  stay valid, and v0.1.1 helpers accept checkpoints that use the new optional lines.
- Update every installed copy together, so all hosts validate the same fields:
  `python3 SKILL/scripts/install.py --project PROJECT --hosts HOSTS --update`.
  It reports local edits and asks before replacing. v0.1.1 copies have no manifest, so review
  any local edits first.
- The project routing block from v0.1.1 keeps working. The v0.2.0 block in
  `references/setup.md` adds "checkpoint after every completed step" and the
  long-operation rule. Replace your block only after reviewing local edits.
- To adopt the new metadata, add `- updated_at: ...` below `writer` at the next save.
- Hooks, the lock and profiles stay off until you enable them.

## Install

Claude Code plugin:

```text
/plugin marketplace add kristianrolando/cross-agent-handoff
/plugin install cross-agent-handoff@cross-agent-tools
```

Direct skill, with the Skills CLI (Node.js 22.20+):

```sh
npx skills add kristianrolando/cross-agent-handoff --skill cross-agent-handoff
```

Or with the bundled installer (Python 3.9+), from a checkout:

```sh
python3 skills/cross-agent-handoff/scripts/install.py --project /path/to/project --hosts claude,codex,antigravity
```

## Validation and limits

Hosted package checks cover Ubuntu, macOS and Windows on Python 3.9 and 3.14. One Claude Code
2.1.318 print-mode session ran the installed SessionStart and Stop hooks, and the model quoted
the injected context. A real v0.1.1 install was upgraded with the installer. StopFailure on a
real rate limit, Codex and Antigravity hooks, Windows hooks, the guard, the lock and the
profiles have not run in live agent sessions; the [live-trial kit](../evidence/live-trial-kit-v0.2.0.md)
lists those trials. Snapshots record what changed, not why. The lock is advisory and cannot
stop edits. See [docs/validation.md](../validation.md) for details.
