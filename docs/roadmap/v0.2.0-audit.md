## Conflicts with docs/architecture.md and the brief's principles

1. Plugin-shipped hooks are not opt-in: Claude merges plugin hooks when the plugin is enabled.
   Proposal: never put hooks in the existing plugin; install them only through an explicit
   install command, or a separate opt-in plugin in the same marketplace.
2. The brief maps Claude `Stop` to the usage-limit case, but the official docs say `Stop`
   does not run on API errors. Proposal: add `StopFailure` and treat per-turn `Stop` snapshots
   as the main coverage for Codex and Antigravity, which document no limit event.
3. Resume-time scanning covers every host without hooks. Proposal: make the inject/scan step
   compare files with the checkpoint time on demand, and keep hook snapshots as an enhancement.
4. Architecture rejects required locks, and SKILL.md says a stale timestamp does not prove
   inactivity. Proposal: keep the lock advisory and opt-in; a stale lock only allows takeover
   after user confirmation and a logged reason. Without hooks, heartbeats never refresh.
5. A YAML front matter block would duplicate the existing metadata bullets, and a format bump
   would make v0.1.1 helper copies reject new checkpoints. Proposal: keep
   `cross-agent-handoff/1` and add optional bullets (`updated_at`, `language`, `profile`).
   Keep `task_status`, `handoff` and `writer` semantics; do not duplicate `## Next`.
6. Two accounts of the same agent share one machine and project, so a stored account alias
   would be wrong after switching. Proposal: alias comes from the per-session prompt or
   environment, is confirmed at takeover, and is never persisted as the identity.
7. A committed `history/` folder and the switch log overlap Git history and Recent outcomes.
   Proposal: defer rolling history; keep `HANDOFF.md.previous`; the switch log is optional.
8. SKILL.md has 1,214 words against a tested 1,600 cap. New procedures belong in references.
