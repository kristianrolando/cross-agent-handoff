## 1. CONTEXT — why this release exists
---------------------------------------------------------------------------

Current state: v0.1.1. The skill lets a user save a compact checkpoint
(HANDOFF.md) in the project so the next agent (Claude Code, Codex, Antigravity,
Cursor, Gemini CLI, GitHub Copilot, OpenCode, Cline) can resume, one writer at
a time.

Primary target user for v0.2.0 (this is also my own daily setup):
- Rotates between several agents AND several accounts of the same agent on the
  SAME project folder, sequentially, switching whenever one hits its usage
  limit. Example rotation: Claude Code (account "claude-A") → Codex →
  Antigravity → Claude Code (account "claude-B").
- Works not only on code but on small games, AI-driven video editing (e.g.
  ffmpeg scripts), and AI-driven motion graphics/animation (e.g. Remotion,
  Manim, Lottie, CSS).

My environment (for testing):
- OS: [ISI: Windows 11 / macOS / Linux]
- Python: [ISI: versi]   Node.js: [ISI: versi]
- Agents available to me for live trials: [ISI: Claude Code (2 akun), Codex,
  Antigravity App/IDE/CLI, ...]

Known weaknesses of v0.1.1 that this release must address (several are
already stated honestly in our own README):
1. No emergency save. Usage limits hit abruptly; the model can no longer write,
   so any progress since the last checkpoint is lost.
2. No single project folder reaches every host: Claude Code and Cline do not
   read `.agents/skills/`; Codex, Antigravity and Gemini CLI do not read
   `.claude/skills/`. Users must maintain two copies by hand and they drift.
3. The checkpoint template is code-oriented. Media projects need asset
   manifests, render settings, visual style rules, and protection against
   duplicate long renders.
4. The sequential checkpoint does not lock anything; nothing stops a user from
   accidentally leaving two writers active.
5. Live-trial evidence exists only for Codex and Antigravity CLI. The Claude
   Code trial on 2026-11-02 could not run because sign-in had expired.
   Antigravity App/IDE has not been exercised.

## 2. PROJECT PRINCIPLES (keep these; challenge them only with reasons)
---------------------------------------------------------------------------

1. Filesystem-based. No cloud service, no cross-vendor API calls, no shared
   chat history, no background daemon.
2. Honest evidence. Always distinguish: documented compatibility ≠ installer
   checked ≠ live model trial. Never claim a live trial that did not happen in
   a recorded session. Never fabricate evidence files.
3. Python 3.9+ standard library only for scripts. No pip dependencies.
   The core workflow must keep working without Python, Node.js or git.
4. Cross-platform: Windows, macOS, Linux. pathlib everywhere, no required
   symlinks, no bash-only logic in core scripts, Windows paths with spaces work.
5. Everything new is OPT-IN. Hooks are never installed without explicit user
   consent. Users who simply update the skill keep the v0.1.1 behavior unless
   they enable new features.
6. Backward compatibility: existing HANDOFF.md checkpoints and existing
   installations must keep working. Any schema change is versioned and
   additive. Provide a migration note if anything changes for existing users.
7. The checkpoint stays COMPACT and links to requirements/architecture/backlog
   instead of duplicating them. It is never a transcript.
8. Privacy: never write emails, tokens or personal data into project files.
   Accounts are referenced by user-chosen aliases only.
9. Do not invent host features. Every host-specific mechanism (hook event
   names, config paths, JSON formats, skill locations) must be verified against
   official documentation or `references/agents.md`. If unverifiable, label it
   "unverified" in the docs and provide a fallback.

If you believe a work package below violates these principles, say so in
Phase 0 and propose an alternative. Principles may be revised only with my
explicit approval, and any revision must be recorded in docs/architecture.md.

## 4. WORK PACKAGES (implement only after approval, in the approved order)
---------------------------------------------------------------------------

Default order: WP1 → WP2 → WP3 → WP4 → WP5 → WP6 → WP7 → WP8.
One branch per WP (`feat/wp1-auto-snapshot`, ...), small Conventional Commits,
one PR per WP with a description that lists verified vs unverified items.
All tests must pass before the next WP starts.

### WP1 — Two-layer auto-save (highest priority)

Rationale: when a limit hits, the model cannot write. Add a MECHANICAL layer
that needs no model, next to the existing SEMANTIC checkpoint written by the
agent.

Deliverables:
- `scripts/snapshot.py` (inside the skill so it ships with every install):
  - timestamp; `git status --porcelain` and `git diff --stat` (skip gracefully
    without git or outside a repo)
  - recently modified files (configurable window, default 120 min), skipping
    .git, node_modules, .handoff, __pycache__ and configurable build/output dirs
  - media files: size + mtime only; NEVER full-hash large files; optional
    partial hash (first + last 1 MB) behind a flag
  - atomic write to `.handoff/auto/latest.json` (temp file + replace)
  - append a one-line summary to `.handoff/auto/history.jsonl`
  - fast (target < 2 s on a typical project); never raises uncaught exceptions;
    always exits 0, logging problems to stderr — it runs inside hooks
- `scripts/inject.py`: prints compact resume context for session start:
  front matter / goal / next action from HANDOFF.md + summary of latest.json.
  Prints a clear WARNING when latest.json is newer than HANDOFF.md (the previous
  agent probably died before saving — recover from actual files, do not trust
  the checkpoint alone). Output capped (configurable, default ~150 lines).
- Claude Code (opt-in): example `hooks/claude-settings.json` plus an installer
  step that MERGES (never overwrites) entries into the project-level
  `.claude/settings.json`: Stop → snapshot.py, PreCompact → snapshot.py,
  SessionStart → inject.py. Verify event names and JSON structure against the
  current Claude Code documentation. Also update the bundled Claude plugin
  wrapper if hooks can be shipped through it (verify).
- Optional staleness guard (separate flag, default off): Stop hook that asks the
  agent to refresh HANDOFF.md when it is stale (> N changed files or > M minutes
  since updated_at). MUST include documented loop protection so it can never
  block indefinitely.
- Codex: verify hook support in official docs; implement equivalent opt-in
  config if supported, otherwise document the fallback.
- Antigravity (App, IDE, CLI): verify hook support. If none, rely on the
  semantic rule and document it.
- Semantic rule block added by init (reviewed, idempotent, removable) to the
  project's AGENTS.md / CLAUDE.md routing:
  - Update the checkpoint after every completed step, before starting the next.
  - Never postpone the checkpoint to the end of the session.
  - Before any long-running operation (render, build, export), record the exact
    command and expected output path under "Running operations".
- Update SKILL.md so resume/recover procedures read latest.json when present.

Acceptance criteria:
- [ ] snapshot.py / inject.py pass CI on Linux, macOS, Windows
- [ ] Works with and without git
- [ ] Abrupt-death scenario: work + snapshot, no semantic save → inject.py
      shows the stale-checkpoint warning and the changed files
- [ ] Hooks opt-in, merged non-destructively, cleanly removable
- [ ] `references/hooks.md` documents each host with verified/unverified labels

### WP2 — One-command multi-host installer and doctor

Deliverables: `scripts/install.py`
- `--hosts claude,codex,antigravity,cursor,gemini,copilot,opencode,cline` →
  copies the complete skill (including LICENSE) to every required
  PROJECT-level location (project level means switching accounts of the same
  agent changes nothing)
- `--user` for user-wide locations where supported
- `--with-hooks` → also runs WP1 hook setup (confirmation required unless
  `--yes`)
- `--doctor` → verifies all copies are identical via `VERSION` +
  `MANIFEST.sha256` per copy, reports drift, checks hooks reference existing
  scripts, checks recommended .gitignore entries
- `--update` → updates every copy together; never nests a copy inside another;
  detects and reports v0.1.1 installs and upgrades them safely
- `--uninstall` → removes installed copies and hook entries only; never deletes
  HANDOFF.md, .handoff/ records or project data
- `--dry-run` for every mutating action
- Keep the existing `npx skills add` route and Claude plugin route working;
  document how they relate to install.py.

Acceptance criteria:
- [ ] Idempotent
- [ ] doctor detects a manually edited copy and a missing copy
- [ ] Upgrade from a v0.1.1 install tested
- [ ] No symlinks; Windows paths with spaces work

### WP3 — Single-writer lock, switch log, checkpoint history

Deliverables:
- `.handoff/lock.json`: {agent, account_alias, host, started_at, heartbeat};
  heartbeat refreshed by snapshot.py. `scripts/lock.py`: acquire, release,
  status, force-release.
- Resume: if the lock is fresh (default heartbeat < 10 min, configurable) and
  held by a different writer, warn and require the user to confirm the previous
  session is closed. Stale locks may be taken over; record the takeover.
- `.handoff/log.jsonl` (append-only): {at, from, to,
  reason: limit|manual|crash|new-session, checkpoint_sha}.
- `.handoff/history/`: rolling copies `YYYY-MM-DD-HHMMSS-<alias>.md`, keep
  last 20 (configurable). Integrate with the helper's existing "previous copy"
  behavior instead of duplicating it.
- Alias resolution: env var `HANDOFF_AGENT_ALIAS`; otherwise ask the user once
  and store it in a gitignored local file — never in committed files.
- Recommended .gitignore: `lock.json`, `auto/`; commit HANDOFF.md, log.jsonl,
  history/ (configurable).

Acceptance criteria:
- [ ] Fresh lock blocks silent resume; stale lock allows logged takeover
- [ ] Atomic writes everywhere
- [ ] History pruning tested

### WP4 — Machine-readable front matter + checkpoint language

Deliverables:
- Optional front matter at the top of HANDOFF.md (schema version bump,
  backward compatible — checkpoints without front matter remain valid):
  schema, updated_at (ISO 8601 with offset), writer (alias), profile,
  status (in_progress|blocked|done), next_action, language
- Minimal strict stdlib parser for this flat `key: value` subset (no PyYAML).
- `language: <code>` (e.g. `id`) → agents write checkpoint prose in that
  language; headings and keys stay English so tooling keeps working.
- Helper validator: structural checks with clear error messages.
- Update the default template, checkpoint-example.md, and SKILL.md.

Acceptance criteria:
- [ ] All v0.1.1-format checkpoints still pass
- [ ] Validator rejects malformed timestamps/statuses clearly

### WP5 — Domain profiles: game, video, motion

Deliverables in `skills/cross-agent-handoff/assets/profiles/`:
- `game.md`: engine + version, run/build command, scenes/levels checklist,
  input mapping, last playtest result, known bugs.
- `video.md`: output spec (resolution, fps, codec, target platform), source
  footage via `.handoff/media-manifest.json` (originals read-only), clip order
  or path to EDL/script, exact final render command, output versions with a
  "latest" marker, running renders (command, output path, start time) with an
  explicit "do NOT re-render" instruction.
- `motion.md`: tool, path to a style-tokens file (colors, fonts, easing,
  durations), composition list with frame ranges and status, preview vs final
  render status.
- Init accepts profiles ("Initialize continuity in this project.
  Profile: video" — combinable). Profiles EXTEND the base template, never
  replace it.
- `scripts/media_manifest.py`: build / refresh / verify (path, size, mtime,
  optional partial hash); verify reports missing and changed assets.
- `assets/style-tokens.json` template + rule: every agent reads it before
  producing visual output.
- `references/profiles.md` explaining when to use each profile, and how
  third parties can contribute new profiles.

Acceptance criteria:
- [ ] Each profile keeps the checkpoint within a defined, tested size budget
- [ ] media_manifest verify detects a changed and a missing file
