# Audit of cross-agent-handoff v0.2.1 (2026-11-26)

Evidence for v0.2.2. The audit was run by an agent workflow for the maintainer: a read-only
analysis of the skill against its use in four of the maintainer's projects, with patches tested
on copies. The report below is the original Indonesian text. Project names were replaced by
labels (Project A: video profile; B: 2D simulation video; C: video and motion profile, no Git;
D: small portfolio project, the only one using the helper), and paths outside this repository
were removed. Findings are labelled `terbukti` (proven) or `dugaan` (suspected); `rendah`
findings were not adversarially verified. Token figures are estimates (characters divided by a
stated ratio). Nothing in it is a live trial of the new routing text.

## Incident record (kept as found)

- The audit's rules forbade writing to the skill repository, the four projects and the agent
  home folders. Two small writes happened anyway. (1) Audit agents ran Python with `-I`, which
  ignores `PYTHONDONTWRITEBYTECODE`, and left three `.pyc` files in the skill's
  `scripts/__pycache__/` (ignored by Git, so no diff). (2) A `git diff` in Project A rewrote
  Git's index stat cache; no tracked content changed.
- After the audit, Project A's `HANDOFF.md` differed from the copy taken at the start (2,289
  words then, 2,405 later; its modification time was 2026-11-26 03:56:47). Several of the
  owner's own sessions in that project were active around that time, so the owner's sessions
  are the likely source. That is not proven. Section 9 below says the four checkpoints were
  unchanged; that was true when the audit ran and is no longer true for Project A.
- The Project A checkpoint and index were not cleaned up or reverted.
- The cold-start scores for Project A used the 2,289-word copy taken at the start.

# Laporan audit cross-agent-handoff v0.2.1

Audit baca-saja atas skill `cross-agent-handoff` v0.2.1 (repo HEAD 27bac5a) dan pemakaiannya di empat proyek: Project A, Project B (Project B), Project C dan Project D. Tanggal: 2026-11-26. Semua status temuan sudah memperhitungkan verifikasi adversarial fase 5 (`notes/verif-*.md`).

## 1. Ringkasan eksekutif

- **Kondisi skill.** Kode kecil (1.649 baris skrip), sehat dan teruji: 82 tes OK di Python 3.9.6 dan 3.15.2, CI 6/6 job. Format `cross-agent-handoff/1` stabil, tetapi helper, `check`, `inject` dan hook hampir tidak pernah dipakai. Di 865 sesi Project A, 6 sesi Project C dan 32 sesi Project B tidak ada satu pun eksekusi `handoff.py`, `check` atau `inject`. Satu-satunya save lewat helper dilakukan Codex di Project D.
- **Pemakaian nyata.** Hampir semuanya Claude ke Claude. Pergantian lintas agen yang terbukti hanya terjadi di Project D (Codex dan Claude, 3 kali). Antigravity di Project A hanya berperan sebagai mesin bawahan.
- **Pola 1. Aturan tidak sampai ke penulis.** Satu-satunya teks yang dimuat setiap sesi, dan yang bertahan setelah `/compact`, adalah blok routing (88-94 kata). Blok itu tidak memuat target ukuran, larangan log, kosakata status atau perintah jam. Akibatnya checkpoint menjadi log tambah-terus di 3 dari 4 proyek: Project A puncak 11.194 kata, Project B 6.967 kata, Project C 14.406 kata. Satu baca penuh di Project C bernilai sekitar 45.500 token (kalibrasi 2,3 kar/token).
- **Pola 2. Kompaksi mengecilkan checkpoint tetapi tidak menyegarkannya.** Butir "menunggu/belum/berjalan" tidak direkonsiliasi: 8 dari 12 butir "menunggu pemilik" di Project A sudah dijawab, dan Project B mencatat folder Y "siap" padahal sudah dihapus. Pertanyaan dan jawaban pemilik dari giliran terakhir hilang (kasus X di Project A, galeri di Project D). Tidak satu pun varian kompaksi memperbaiki keusangan ini.
- **Pola 3. Penulis dan operasi aktif tidak terlihat.** Metadata `ready/none` hampir permanen (Project B 105/105 versi). Sesi paralel dan sesi operasi tidak tercatat, misalnya 40 unggahan YouTube yang berjalan saat checkpoint menyatakan "tanpa unggahan aktif". Perintah yang tercatat di checkpoint sempat dijalankan sebagai probe dan mengunggah 1 video tanpa izin jumlah.
- **Arah v0.2.2.** Perbaikan kecil dan aman: teks blok routing (anggaran, `date -Iseconds`, tulis ulang di tempat, rekonsiliasi butir terbuka, larangan probe), lalu patch kode yang sudah teruji: exit 0 hook, timeout git, label operasi, UTF-8, hook `--shared`.
- **Arah v0.3.0.** Kompaksi gaya alt-A (peringatan berlokasi per bagian, tanpa penolakan ready), didahului salinan utuh berkas lama ke nama unik (`cp`). Rotasi per butir, Beads dan hook untuk lima host lain ditunda karena belum ada bukti pemakaian yang mendukungnya.

## 4. Biaya dan kinerja

**Metode token.** Token diestimasi sebagai karakter / 3,5, kecuali bila disebut "terkalibrasi". Rasio terkalibrasi berasal dari delta `message.usage` di transkrip di sekitar pemanggilan Read: Project A 1,9 kar/token (n=15), Project C 2,3 (n=9), Project D 2,19 (n=51), Project B 1,96-2,0 (n=2). Teks berbahasa Indonesia ternyata 1,5-1,9 kali lebih mahal daripada perkiraan kar/3,5. Waktu diukur dengan `/usr/bin/time -p`.

**Pengukuran helper (sintetis).** Repo 60.000 berkas: Stop snapshot 0,58 s, `--guard` 1,09 s, inject 0,55 s. `scan_truncated` dilaporkan dengan benar. Berkas 8 GB tracked yang di-touch: `ls-files --modified` 11,71 s (lewat timeout 5 s), inject 5,09 s tanpa peringatan, Stop+guard 20,56 s (F15). `inspect --file` 1 GB: RSS 1,10 GB, turun ke 26 MB dengan patch (F33). Varian scan dengan prefix relatif 2-5 kali lebih cepat (F34). Kontensi `index.lock`: 25/232 dan 40/242 kegagalan `git add` paralel (F16). Suite 82 tes: 6,1 s (3.15) dan 11,6 s (3.9).

**Tiga pemborosan terbesar.**
1. Membaca checkpoint gemuk. Project C ≈45.500 token per baca penuh (terkalibrasi), padahal target 1.200 kata ≈3.800 token. Project B sesi 8bde5b62 menanggung ≈6,6 juta cache-read untuk 304 panggilan. Sekitar 90% isinya riwayat yang sudah selesai.
2. Save tambah-terus. Project C ≤150 rb output token untuk 129 tulisan yang sebagian besar menambah log, dan setiap tulisan menaikkan biaya baca berikutnya sekitar 111 kata.
3. Listing skill dan teks yang tidak dipakai. Listing ganda di Project D (plugin + salinan) memakan ≈130 token per panggilan. `skill_listing` di Project C (≈143 token per sesi) tidak pernah dipanggil. Blok routing termuat di 829 job headless Project A yang tidak memerlukannya. Pos ini kecil, tetapi muncul di setiap sesi.
